Facts about PSBD-ViT that change how a result should be read. Re-verify against the code before acting on any of them; re-checked 2026-08-16.

**Clean-label and source-specific poison rates silently cap.** `poison.choose_poison_indices` (poison.py:119) and `choose_indices_with_cover` take `min(round(rate * len(dataset)), len(eligible_pool))`. For `sig`/`lc` the eligible pool is only the target class (500 images on CIFAR-100), and for `tact` only the source classes. So on CIFAR-100 the 0.01, 0.05 and 0.1 clean-label checkpoints are all the same realized 1% poisoning, while `args.json`/`metrics.json` report the requested rate. `sig` shows it cleanly (ASR 0.2498 at 1% vs 0.2516 at 5%). `lc` does NOT look identical (ASR 0.874 / 0.543 / 0.786 at 1/5/10%) because 557 of the tracked `checkpoints/*/args.json` carry `"seed": null`, so those are 3 unseeded runs of the same poisoning; the spread is seed variance, which is worse than a duplicate row, not better.
**Why:** any poison-rate trend line for sig/lc/tact on CIFAR-100 is measuring seed noise between identical poisonings, and any table citing those rates is wrong. `defence_tables.py` PANEL still includes `lc` across all 3 rate tags.
**How to apply:** when reviewing or writing up rate sweeps, treat clean-label and TaCT rows as a single realized rate unless the cap has been fixed and the models retrained. Do not read a non-monotonic clean-label ASR as evidence the cap is absent.

**PSBD here is reframed from the paper.** The published method scores the *suspicious training set*; this repo scores held-out *test* images (clean vs triggered) and reports TPR/FPR/AUROC over that. Also `PSBD_HELDOUT_SIZE = 2000` is fixed, where the paper uses 5% of the training set, and training normalizes inputs where the paper explicitly does not.
**Why:** these make the numbers non-comparable to PSBD's published table even when the code is internally correct.
**How to apply:** flag any claim that compares a PSBD-ViT number to the paper's reported number; the reframing has to be stated as a divergence, not assumed equivalent.

**Training-time PSU has the opposite sign from eval-time PSU, early and on training data.** Measured in the H25 adaptive-attacker logs: poisoned-sample PSU sits ABOVE clean PSU for the first several epochs (memorized poisoned samples start at confidence ~1, and absolute PSU is bounded by the base confidence), inverting only late in training if at all. At a saturating probe rate the perturbed pass goes near-uniform, PSU degenerates to base confidence, and the inversion never happens.
**Why:** any loss term or diagnostic defined as `mean_clean_PSU - mean_poisoned_PSU` computed inside the training loop is inactive or backwards unless the probe rate is calibrated to the defender's operating sigma.
**How to apply:** when reviewing anything that computes PSU during training, check the realized disturbance (is the perturbed probability near 1/num_classes?) before believing the statistic; and check whether the split is train or test.

**badnet_a2a ASR is around 0.50 at 1% poison on CIFAR-100.** The `AttackSuccessSet` "backdoor" split contains every triggered image regardless of whether the trigger actually flipped it. Since addressed: `psbd_analyze.analyze_one_rate` writes a `detection_captured_only` block that restricts BOTH sides with `attack_success_mask`; restricting only the backdoor side is the known confound that scored the benign control at 0.921.
**Why:** for all-to-all, roughly half the detector's positive set is not behaviourally backdoored, so a low TPR cannot be read as "the detector failed."
**How to apply:** any all-to-all falsification probe should quote `detection_captured_only`, not `detection`. `defence_tables.py` and `psbd_variants.py` do not compute it at all.

**The one-sided rule is a standing project rule, and 2 live scripts break it.** `docs/hypothesis/H15-...md` lines 17-21 retire two-sided scoring outright: no `max(AUROC, 1-AUROC)`, no per-checkpoint tail selection, no double thresholding; `auroc_two_sided` and `direction` in `psbd_metrics.json` are diagnostics that must not appear in a table. As of 2026-08-16 `psbd_variants.py` (the `psbd_vit` variant, source of H13's headline) and `psbd_operating_points.py` still select the tail from the ground-truth clean/backdoor split.
**Why:** choosing which tail to flag reads the poison labels the detector exists to predict, so any number produced that way is an oracle upper bound, not a result.
**How to apply:** when auditing or citing a PSBD-ViT number, check which script produced it. `psbd_analyze.py`, `defence_tables.py`, `baseline_detect.py`, `detector_fusion.py` and everything in `scratch/` are one-sided and clean.

**Every `token_mask` cache on disk carries a CLS-amplification artefact.** `defences/perturbations.py:124-126` protects token 0 from masking but then multiplies the whole tensor, CLS included, by `1/(1-rate)`. So on ViT the classifier's read token is deterministically amplified 2x at p=0.5 and 10x at p=0.9 on top of the masking. It vanishes only where a LayerNorm immediately consumes the hooked tensor (`before_attention_norm`, `before_mlp_norm`, both pre-hooks on ln_1/ln_2); at `after_embedding`, `before_attention`, `mlp_neurons` and every residual position it persists into the stream. Swin takes the 4-D branch with `protect_cls=False` and is unaffected.
**Why:** H27's attack-ordering table is at `before_attention_norm` and survives, but its "three of the top six full-coverage rows" claim rests on `before_mlp_residual` and `mlp_neurons`, which do not. ViT-vs-Swin `token_mask` comparisons are confounded regardless of position.
**How to apply:** treat any `*_token_mask` cache written before this is fixed as measuring masking-plus-gain, and re-run rather than re-analyse. Fixing the code does not fix the tensors already in `results/*/psbd/`.

**Two different "sigma-matched" rate rules coexist.** `defences.psbd_metrics.select_rate_at_matched_shift` (used by `psbd_analyze.py`, so by every `psbd_metrics.json` and by H21-H27) picks the rate whose clean-validation sigma is *closest* to the target. `defence_tables.py:86-95` picks the *first ascending rate at or above* the target, and returns None when none does.
**Why:** the two disagree whenever the grid is coarse or an operator climbs slowly, so a `defence_tables.py` row can differ from an already-published hypothesis number for an identical configuration, and coverage gaps like H27's appear or disappear depending on which script ran.
**How to apply:** never put a `defence_tables.py` number next to an H2x number without checking they used the same rule.

**557 of the tracked `checkpoints/*/args.json` are provenance-null.** They carry `"seed": null, "git_commit": null, "trained_started_at": null` and no `clean_accuracy`/`asr`/`max_samples` keys, because they were backfilled by the `normalize_checkpoints.py` migration rather than written by `train.checkpoint_metadata`. The CLAUDE.md rule "every folder gets an args.json" is satisfied by a file whose fields are null.
**Why:** the code version behind those weights is unknown, so a cross-cell comparison cannot rule out that two cells were trained by different code. Empirically `vit_cifar100_lc_{0_01,0_05,0_1}` are the SAME 500 poisoned images (the cap) yet report ASR 0.874 / 0.543 / 0.786; `lc_0_005` at a genuinely different 250 images reports 0.015. So the fleet carries an unquantified ~0.33 ASR band between runs that should be identical.
**How to apply:** treat 0.33 as the current empirical upper bound on run-to-run ASR noise until someone runs a real 2-seed replicate; do not read any single-cell ASR or AUROC difference below that as signal. Ask for `git_commit` before comparing two checkpoints trained at different times.

**Two baseline/operator implementations diverge from their sources in ways that shift the comparison.** `defences/baselines.py:111` superimposes STRIP's overlays on *normalized* tensors (`images + overlay`), so every blend also subtracts one extra dataset mean; the paper blends in 0-to-1 pixel space. `defences/perturbations.py:173` scales GaussianNoise by `x.detach().std()` over the whole batch, so the clean split and the all-triggered backdoor split get different noise magnitudes and the score depends on batch size.
**Why:** both silently move the baseline PSBD is being compared against, and the gaussian one is the control H23/H28 lean on.
**How to apply:** when a table shows PSBD beating STRIP, note that STRIP was run with an extra constant offset; when quoting gaussian numbers, note the noise scale was per-batch, not per-sample.

**The adaptive attacker optimizes a different statistic on Swin than the defence measures.** `adaptive_evasion.psu_for_batch` runs inside `model.train()`, and `swin_s` ships `stochastic_depth_prob=0.3`, so both the "unperturbed" baseline and the probe passes are computed with stochastic depth live; at eval time `defences.inference` computes both with it off. ViT is unaffected (all built-in dropouts are p=0). The attacker also uses `--evade-passes 2` where the defender uses `k=3`.
**How to apply:** a failed evasion on a `pbs/psbd_evade/ev_s_*` (Swin) run is not evidence the defence survived an adaptive attacker.

**Placement/operator selection is an oracle even though rate selection is not.** `psbd_metrics.select_rate_by_oracle` is honestly labelled and matched-sigma rate selection reads clean validation only, but H28's "27 operator/position combinations sorted by 1% AUROC" picks the winner by reading the same backdoor split it reports on.
**How to apply:** any "best placement" headline needs held-out confirmation (choose on a subset of attacks/datasets, report on the rest) or must be labelled an upper bound.

**The ASR-set core is clean; do not re-audit it every review.** Full trace 2026-08-16: `poison.AttackSuccessSet` + `is_eval_poisonable`/`attack_success_label` is the only live eval-time ASR path, reached through `loaders.build_poisoned_loader` (used by `evaluate.evaluate_attack`, so by `metrics.py` and `train_backdoor.py`) and `defences.checkpoint_eval.build_psbd_loaders_from_checkpoint` (used by the sweep, `baseline_detect`, `detector_fusion`, `scripts/backdoor_neurons/ablate`). Training uses `is_poisonable`/`poisoned_label` and nothing else. No train/eval crossover anywhere live; SIG/LC eligibility inverts correctly; a2o/a2a are consistent at both ends. Dead-but-tracked and NOT to be trusted if resurrected: `backdoor_data.PngPathDataset` + `utils.config.label_mode_from_folder` (BackdoorBench PNG path, correct but only called from `_archive/sweep.py`), and `defences.checkpoint_eval.build_eval_loaders_from_attack`/`_from_checkpoint`, which filter eligibility *after* `balance_by_class` and so break the clean-vs-backdoor pairing rule.
**Why:** this path has now been audited several times with no finding; the leaks that do exist are all downstream, in the scripts that consume the splits.
**How to apply:** on an ASR-correctness review, confirm the entry points still route through `AttackSuccessSet` and spend the remaining effort on the consuming scripts. Two latent traps to re-check only if they become reachable: `evaluate.evaluate_checkpoint` rebuilds the attack from `default_config(args["attack"])` and ignores the recorded `label_mode` (no cross-check, unlike `build_psbd_loaders_from_checkpoint`), and `AttackSuccessSet` passes a *subset-local* index to `apply_trigger`, which only `attacks/generated.py` reads.
