# Status, 2026-09-09: clean-label attacks, checkpoint integrity, and what comes next

Entry point for the work of 2026-09-09. Four findings, three of them defects that were
silently corrupting results or about to, plus the fixes and the queue. Detail lives in
the linked documents; this page is the map.

---

## The four findings

### 1. The clean-label rate cap now has a fix, and a hard limit

The cap itself was already known: audit finding A8 (2026-09-07) established it and
backfilled `realized_poison_rate` into every `args.json`, and
`notebooks/04-datasets-and-splits.ipynb` derives it from the library. A8 said what was
wrong and stopped there. **189 of the 316 clean-label folders are affected** (99 ViT,
90 Swin; A8 counted 180 and the set has grown).

What is new is the separation of the fixable part from the permanent part.

| dataset | cap at class 0 | best cap | reachable of 0.5 / 1 / 5 / 10% |
|---|---:|---:|---|
| cifar10 | 10.00% | 10.00% | all four |
| cifar100 | 1.00% | 1.00% | 0.5, 1 |
| gtsrb | 0.56% | **5.63%** (class 1 or 2) | 0.5, 1, 5 |
| tiny | 0.50% | 0.50% | 0.5 only |

Permanent consequences: **10% clean-label is impossible outside CIFAR-10**, 5% is
impossible on CIFAR-100 and Tiny, and 1% is impossible on Tiny. Since the panel declares
rates `[0.01, 0.05, 0.1]`, **Tiny clean-label cells cannot be panel cells at all** and
CIFAR-100 contributes only its 1% cell. Those are dataset properties, not sweep gaps.

The fixable part is GTSRB, the only dataset that is not class-uniform: switching the
clean-label target from class 0 (150 images) to class 1 (1,500) lifts its cap 10x and
buys back the 1% and 5% cells. CIFAR-100 and Tiny are uniform, so no choice of target
helps them at all.

Full arithmetic and the fixes: [clean-label-rate-caps.md](clean-label-rate-caps.md).

### 2. Label-Consistent was implemented as its own weak half

Turner et al. perturb each base image adversarially before stamping the patch, so the
image stops supporting its own label and the trigger becomes the only reliable cue. That
step was never implemented; the docstring said so. Hence the patch-only variant needing
essentially the whole target class before it implants: CIFAR-10 clears only at 10%, which
*is* 100% of the target class.

The PSBD paper we are porting used precomputed adversarial images throughout
(`papers/PSBD/sec/7_appendix.tex:543-546`), so this was a gap against the reference too.

Now implemented as `psbd/adversarial.py` (untargeted L-infinity PGD against a clean
surrogate) plus `cli/lc_bases.py`. Verified on the surrogate before any victim trains:
GTSRB class 1 target-class accuracy **1.000 -> 0.043**, CIFAR-100 **0.984 -> 0.000**, with
perturbations inside the L-infinity ball and inside `[0, 1]`.

### 3. 21 checkpoints were being written as files, and the WaNet sweep was losing runs live

Two job generators passed `--output checkpoints/<name>` instead of
`checkpoints/<name>/attack_result.pt`. `save_checkpoint` then wrote a 343 MB plain file
named `<name>` and dropped its sidecar at `checkpoints/args.json`, which every subsequent
affected run overwrote. The coverage ledger only descends into directories, so these runs
were invisible rather than reported broken, which is how it went unnoticed for four weeks.

**Seven of the affected runs were from the WaNet strength sweep, which was actively
destroying its own results as it produced them**, with 14 more jobs queued behind them.

All 21 were recovered, plus 1 more that landed afterwards from a job already running when the fix went in (a running process has the old code imported, so only queued jobs pick the fix up at launch). The fix went into `save_checkpoint` rather than the generators,
because PBS copies a job script at submission time and the queued jobs needed to be fixed
at runtime. Detail:
[checkpoint-integrity-2026-09-09.md](checkpoint-integrity-2026-09-09.md).

### 4. A repeated command-line flag kept only its last value

Caught while verifying the fix for finding 2, and it would have silently undone it.

Label-Consistent needs 2 configuration values, the directory holding its adversarial
bases and the epsilon those bases carry. Written the natural way, as 2
`--attack-override` flags, only the second survived: the argument was declared
`nargs="*"`, which replaces rather than accumulates. With `adversarial_dir` empty the
attack falls back to its patch-only variant, so **every "adversarial" run would have
trained the weak attack while its `args.json` advertised the strong one.**

The end-to-end smoke run passed. Training completed, ASR and clean accuracy were
recorded, and the missing-bases check did not fire, because with no directory configured
there is nothing to be missing. The only visible symptom was one absent key in a metadata
dict.

Fixed three ways, because the flag was only the surface: the argument now uses
`action="extend"`, the generator passes both keys in one flag, and **a configuration
carrying an epsilon with no directory is refused before training starts**
(`attacks.adversarial_config_error`). The third is the one that catches the incoherent
state whatever produced it, and it is unit-tested.

## The result that came out of the recovery

The WaNet question — why it never implants at 1% — now has an answer for one dataset.
At 1% poisoning:

| dataset | strength 0.5 (default) | 1.0 | 2.0 | 4.0 |
|---|---:|---:|---:|---:|
| cifar10 | 0.112 | 0.165 | 0.775 | 0.757 |
| cifar100 | 0.057 | 0.167 | 0.569 | 0.792 |
| gtsrb | 0.119 | 0.838 | **0.934** | **0.918** |

**GTSRB clears at strength 2.0**: ASR 0.934, clean accuracy 0.987 against a benign 0.991,
so the cost is 0.004. Strength 4.0 also clears but buys nothing, so 2.0 is the dose to
adopt. CIFAR-10 and CIFAR-100 are climbing steeply but need strength 8 or higher.

The failure taxonomy this sits in — four distinct causes, only two fixable — is in
[attack-strength-and-implantation.md](attack-strength-and-implantation.md).

## A number worth internalising: the single-run error bar

The clean-label cap accidentally produced replicates. Three CIFAR-100 `lc` runs at
identical configurations, down to the poisoned index set, read **0.873 / 0.545 / 0.785**.
Three GTSRB `lc` runs read **0.464 / 0.239 / 0.129**. Spreads of 0.33 and 0.34.

Those runs predate the seeding commit, so they differ only by an unrecorded random
initialisation and shuffle. **A hard ASR bar of 0.85 applied to a single training run is
not a reliable classification at that spread.** Every new cell here is trained at seeds 0
to 4 and reported as a mean with a spread.

## What changed in the code

| area | change |
|---|---|
| `psbd/adversarial.py`, `cli/lc_bases.py` | new: PGD base generation, atomic cache, tracked manifest |
| `attacks/lc.py`, `psbd/attacks/lc.py` | adversarial bases at train time, patch-only at eval time, defaults inert |
| `attacks/_bases.py`, `psbd/attacks/_bases.py` | new: lazy index-keyed base lookup and coverage check |
| `train.py`, `psbd/training.py` | `resolve_checkpoint_path` normalizes folder-form `--output` |
| `train_backdoor.py`, `cli/train_backdoor.py` | refuse to train if a poisoned index has no base |
| `stealth.py`, `psbd/stealth.py` | read through the eval trigger, matching `AttackSuccessSet` |
| all four training entrypoints | `seed_everything(seed, workers=True)` |
| `scripts/coverage_ledger.py` | canonical-variant filter; `pivot_configs` no longer overwrites silently |
| `configs/psbd_basis.json` | `canonical_variants: {"lc": "_adv"}`, `_pilot` excluded |
| `scripts/backfill_metadata.py` | null seed no longer means `default_rng(None)` |
| `pbs/generate_cleanlabel_jobs.py` | new: emits only reachable rates, computed from the data |
| `pbs/generate_trigger_sweep_jobs.py`, `generate_retrain_jobs.py` | output-path fix |

Naming for the new cells:
`{arch}_{dataset}_{attack}_{rate_tag}[_tl{N}][_adv][_seed_{n}]`. `_tl{N}` is a
non-default target class, `_adv` is Label-Consistent with its adversarial bases and is
what `psbd_basis.json` names canonical, so the older patch-only runs keep their folders
without competing for a panel slot.

**The `lc` column has left the coverage panel, on purpose.** `canonical_variants`
admits only `_adv` folders as `lc` cells, and none exist yet, so
`results/coverage/COVERAGE.md` now shows 8 attacks rather than 9 and the panel is
96 cells rather than 108. That is the old patch-only runs standing down, not
measurements being lost: they remain on disk and remain readable. The column
returns, with cells that mean what they say, once the adversarial runs land and
`pbs/generate_basis_jobs.py` sweeps them.

**Old checkpoints are untouched.** LC's new config fields default to inert, so
`default_config("lc")` reproduces the previous behaviour byte for byte; that is pinned by
`tests/test_rewrite_library.py` and `test_lc_default_config_is_the_patch_only_variant`.

## Open issues

1. **`sig` has no fix on CIFAR-100 and Tiny.** It inherits the target-class change on
   GTSRB, but the other two cap at 1% and 0.5% and it does not implant there at any
   reachable rate. Either raise the sinusoid amplitude above Barni's 40/255 and declare
   it, or report that SIG does not implant at the maximum achievable clean-label rate on
   many-class datasets. The second is a legitimate finding.
2. **Two broken training runs** need retraining, not analysis: `vit_gtsrb_tact_0_01`
   (ASR 0.000, clean accuracy 0.121 against a benign 0.991) and
   `vit_gtsrb_badnet_a2a_0_01` (ASR 0.048 between 0.759 and 0.931 on either side).
3. **Adaptive-Blend fails at seed 0 on all four datasets** but clears at seeds 1 and 2.
   The asymmetric-trigger correction is committed but untested at scale.
4. **Every table with a clean-label row has to be re-read**, since those rows reported
   rates that were never applied.
5. **A run can still succeed and produce nothing readable.** The ledger reports missing
   cells, not malformed ones; it should treat a plain file in `checkpoints/` as an error.
   Relatedly, a checkpoint `.pt` holds only `model` and `num_classes`, so nothing inside
   it identifies the run.
6. **521 checkpoints are not reproducible** (unseeded training, pre-`9f6acfb`). Left as
   they are by decision: they are valid experiments and nobody re-runs training to check
   a number. Only the forward fix was applied.
7. **Notebook outputs drift silently, and the drift check does not catch it.**
   `00-start-here` reports an `errors` column per notebook, but it counts errors
   *stored from the last execution*, so a notebook broken by a later library change
   still reports 0. Notebook 03 was in exactly that state: it reported 0 errors
   while failing on its second cell, because the attack registry had grown by 7
   `badnet_a2m*` entries and Adaptive-Blend's trigger had become deliberately
   asymmetric. Notebooks 00, 03, 04 and 12 were re-executed on 2026-09-09; the
   other 11 carry older outputs and may have drifted the same way. Re-executing
   them is cheap for the CPU-only ones and is the only real check.
8. **Two pre-existing test failures** remain at HEAD and are unrelated to this work:
   `test_flag_parity_with_original[cli.sweep-psbd_dropout_sweep]` and
   `test_summary_writes_a_versionable_csv`.
